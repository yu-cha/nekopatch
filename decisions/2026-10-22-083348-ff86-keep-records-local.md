# ff86 クリアの記録は今の localStorage のキーと形のまま上限なく置き、消さないよう頼む。確かめ用のページは別のキーを使う

## 結論

- クリアの記録は、作り直す前と同じ localStorage のキー `nekopatch-history-v1` に、同じ形（`{at, n, d, t, h}` の JSON の配列）で置く。遊びかけの盤面と「クリア ○ 問」の数も、同じキー `nekopatch-v1` に同じ形で置く。引き継ぎの処理は要らない。
- 記録の数の上限（元の `slice(-500)`）は置かない。
- 起動したときと「記録」を開いたときに `navigator.storage.persist()` で消さないよう頼み、結果を「記録」の画面に出す。
- Web App Manifest（`manifest.webmanifest`、猫のアイコン、`display: standalone`）を置き、ホーム画面に追加したときに、インストールしたアプリとして扱われやすくする（ナンの答え 2026-10-22 の ⑤ A）。
- 保存してある値が読めない（JSON でない、形が違う）ときは、元の文字を `<キー>-unreadable-<日時>` に残してから書き直す。残せなければ、そのキーには書かない。
- 機種変更のときのファイルは JSON（`nekopatch-records-<日付>.json`）。中身は `format: "nekopatch-records"`、`version: 1`、`solvedCount`、`records`。読み込みは、1 か所でも読めなければ何も変えない。
- 確かめ用のページ（`vite build --mode trial`）は、キーを `nekopatch-preview-` で始める。最初に開いたとき、本物のキーの値を写して使う。本物のキーには書かない（書こうとしたら止める仕組みを `trialStorage` に置き、テストで確かめる）。

## 背景

- ナンとの合意（2026-10-21）: 記録はスマホの Chrome の中だけに残す。500 回の上限をなくす。消さないよう頼み、結果を「記録」の画面に出す。機種変更のときだけ書き出しと読み込みを使う。
- ナンの今までの記録は、ナンのスマホの Chrome の localStorage にだけある。
- Chrome は、空き容量が少ないとき、persist されていないオリジンのデータを、最近使っていない順に、オリジンごとまとめて消す。Storage 標準では、localStorage も IndexedDB と同じ「バケット」に入り、persist が通れば守られる（2026-10-21 に調べた。web.dev の persistent-storage、MDN の Storage quotas and eviction criteria、storage.spec.whatwg.org）。
- Chrome は確認の画面を出さず、よく使うサイトか、インストールやブックマークをしたか、通知の許可があるか、で決める。manifest の無いサイトをホーム画面に追加して、インストールに数えられるかは、確かめられなかった。

## 検討した選択肢

- 置き場所:
  - **今の localStorage のキーのまま**（採用）: 今までの記録を、移す処理なしで読める。移す処理の不具合で記録を失うおそれが無い。1 件は 50 文字ほどで、Chrome の localStorage の上限（オリジンごとに数 MB）でも数万件入る。1 日 10 回クリアしても 10 年以上もつ。
  - **IndexedDB に移す**: 容量は大きいが、移す処理が要り、記録を失うおそれが増える。今の量では要らない。
- 書き出すファイルの形:
  - **JSON**（採用）: そのまま読み書きでき、形を確かめやすい。記録を 1 件 1 行にして、開いても読めるようにした。
  - **CSV**: スプシで開けるが、「クリア ○ 問」の数を一緒に入れにくい。合意では、スプシで見ることは求められていない。
- 確かめ用のページの記録:
  - **別のキーに写して使う**（採用）: ナンが今までの記録で確かめられ、本物は変わらない。
  - **空の記録で始める**: 安全だが、今までの記録の見え方を確かめられない。

## 理由

- 合意の「今までの記録は必ず引き継ぐ」を、移す処理を作らずに満たせる。
- 確かめ用のページを本物と同じオリジンに置く以上、本物のキーに書かないことを、仕組みとテストで守る必要がある。

## 影響・見直す条件

- 作り直す前の版（`slice(-500)` のある版）に戻すと、500 件を超えた記録は、次のクリアで古い方から消える。戻すときは、先に書き出しておく。
- 記録が数万件を超えて、保存に失敗する（「記録」の画面に知らせが出る）ようになったら、IndexedDB に移すか、古い記録をまとめる形を検討する。
- persist が通らないことが多いと分かったら、案内（ホーム画面への追加）を見直す。
