# df3b GitHub Pages でそのまま配信し、検査の仕組みは置かない

## 結論

- 受け取った `nekopatch.html` を、手を加えずに `index.html` として置く。
- GitHub Pages で、`main` ブランチの最上位をそのまま配信する（ビルドも GitHub Actions も使わない）。アドレスは https://yu-cha.github.io/nekopatch/ 。
- `.nojekyll` を置き、GitHub Pages の Jekyll による変換を止める。
- 全アプリ共通の標準（TypeScript の雛形 798a、共有フォルダの一覧 382f）には従わない。リンター、テスト、`justfile` は置かない。

## 背景

- 2026-10-21、ナンから「これをギットハブページで遊べるようにして」と、1 つの HTML で動くパズルのゲームを渡された。
- ナンの答え（2026-10-21）:
  - リポジトリも公開してよい（無料のプランで Pages を使うため）。
  - アドレスは、ゲームを集める場所ではなく、ねこパッチ専用にする。
  - あとで直す予定は無く、このまま置くだけ。
- ゲームは外部に Google Fonts を読み込むだけで、サーバーへの送信は無い。記録はブラウザの localStorage（キー `nekopatch-v1`、`nekopatch-history-v1`）に残る。個人の情報は含まない。

## 検討した選択肢

- 配信の仕方:
  - **ブランチの最上位をそのまま配信**（採用）: 設定が少なく、`main` に取り込むだけで反映される。
  - **GitHub Actions で配信**: ビルドや検査を挟めるが、ビルドの無い 1 ファイルには手間だけが増える。
- 作り:
  - **そのまま置く**（採用）: ナンの希望。今の動きを変えない。
  - **TypeScript の雛形（798a）に作り直し、ロジックと UI を分けて検査を置く**: 直し続けるなら劣化を防げるが、直す予定が無いので見合わない。

## 理由

- ナンは直す予定が無いと答えたため、劣化を防ぐ仕組みの出番が無い。
- 公開のページなので、VM の共有フォルダの一覧（382f）に置かなくても、Windows やスマートフォンのブラウザから開ける。

## 影響・見直す条件

- `yu-cha.github.io` の下のページ（今後ほかのリポジトリで Pages を使ったとき）は、ブラウザの保存領域を共有する。ゲームのキーは `nekopatch-` で区切られているので、今は問題ない。
- ナンから直しや遊び方の追加を頼まれたら、そのときに、ロジック（問題の生成と解き方、今の `<script id="core">`）を UI から分け、テストとリンターを置く形（798a）に作り直すかを決める。小さな直し 1 回なら、そのまま直してもよい。
