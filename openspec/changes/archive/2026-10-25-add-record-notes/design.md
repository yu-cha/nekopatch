# Design

## Context

- 記録は `nekopatch-history-v1`（`{at, n, d, t, h}` の配列。ff86）、盤面の形は `nekopatch-boards-v1`（記録の鍵 → 盤面の符号。490d）、遊びかけの盤面と設定と「クリア ○ 問」は `nekopatch-v1` にある。
- 今配信している版（490d の版）は、記録を 5 つの値だけの形で保存し直し、知らないキーには触らない。`nekopatch-v1` は、知らない欄を読み飛ばす（`parseSavedGame` は決まった欄だけを読む）。
- 記録の一覧の「新しい順」の表は、日時・盤面・タイム・ヒント・遊ぶの 5 列で、スマホの幅（360px ほど）で「遊ぶ」まで見えるよう、セルを 2 段にしてある。表は HTML の文字列を `innerHTML` に入れて作っている。
- クリアは、猫を置いた操作（なぞり終わり、ヒントの「猫を置く」）の中の `render` から `onWin` で起きる。「猫の周りに自動で×」は、その操作の中の `autoXAround` で × を付ける。
- キー操作（N で新しい問題、H でヒント、Ctrl+Z / Ctrl+Y）は文書全体で受けていて、今は `select` の上だけを除いている。

## Goals / Non-Goals

**Goals:**

- 備考と「自動×」の印を、今の版のタブが残っていても、その版に戻しても失わない。
- ナンが書いた文を、どこに出しても HTML として扱わない。
- 今のスマホの幅で、一覧が崩れない（✎ の列を足しても「遊ぶ」まで見える）。

**Non-Goals:**

- 備考や印で絞り込む・数える仕組み。
- 盤面ごとの並びで、記録 1 件ずつの備考を見ること。

## Decisions

1. **置き場所は別のキー `nekopatch-notes-v1`**（判断 c995）。`{"<at|n|d|t|h>": {"memo"?: string, "hard"?: true, "autoX"?: true}}`。何も無い記録の鍵は消す。ロジックは `src/core/notes.ts` に置き、`records.ts` の書き出し・読み込み・盤面ごとの並びから使う。
2. **文の整え方**（`cleanMemo`）: 制御文字（`\p{Cc}`）を除き、前後の空白を除き、符号位置で 30 文字までにする。画面の欄にも `maxlength="30"` を付ける。保存してある値とファイルの値は、文字列なら切らずに読む。
3. **読むとき**（`parseStoredNotes`）: 鍵が記録の鍵の形（数 5 つを `|` でつないだもの）で、値がオブジェクトで、`memo` が文字列、`hard` と `autoX` が真偽値（無くてもよい）のものだけを使う。1 つでも外れたら `intact: false` を返し、`SaveStore` が元の文字を `<キー>-unreadable-<日時>` に残してから、読めた分で書き直す（490d と同じ）。`memo` が空、`hard`・`autoX` が `false` の欄は、無いものとして読む。
4. **「自動×」を使ったか**は、画面の状態 `autoXUsed` に持つ。`autoXAround` で、設定が ON なら `true` にする（× が 1 つも増えなくても、ON のまま猫を置いたので）。新しい問題・もう一度遊ぶ盤面（`setPuzzle` で状態を作り直すとき）で `false` に戻す。「戻す」「最初から」では戻さない。遊びかけの保存（`nekopatch-v1`）には、`true` のときだけ `autoXUsed: true` を書く（`serializeGame`）。読むときは `autoXUsed === true` だけを `true` にする。
5. **クリアしたとき**: 記録の鍵で備考の項目を作る（`autoXUsed` なら `autoX: true`）。盤面の形 → 備考と印 → 記録の順に保存する（どれかに失敗しても、余るのは記録の無い鍵だけ）。クリアの画面には、ヒントの回数の横に「　自動×」、前回の記録（`compareWin` の `prev`）に備考があれば「前回の備考: 」と印と文を出す。文は `textContent` で入れる。
6. **書く欄の保存**（`updateNote(鍵, 変え方)`）: 保存の前に `syncFromStore` で、記録・盤面の形・備考をほかのタブの分まで読み直し、その鍵の項目だけを変えて保存する。記録がもう無い鍵（ほかのタブで全部消した）には書かない。文は `change`（決定、欄の外を押す）と、ほかのアプリに切り替えたとき（`visibilitychange`）に保存する。「次の問題」「もう一度この盤面」「閉じる」を押すと、欄から外れて `change` が起きる。
7. **記録の一覧の新しい順**: 先頭に ✎ の列を足す（`<button class="note" data-k="<記録の鍵>">`。鍵は数と `|` だけなので、属性にそのまま書ける）。備考のある記録の次に、`<tr class="noteRow">` を足し、`<span class="hard">難</span>` と `<span class="memo" data-k="…">` を置く。表を `innerHTML` で作ったあと、`.memo` に `textContent` で文を入れる。✎ で開いた記録は、備考の行の代わりに書く欄の行（`noteEdit`）を出し、欄の値も `value` で入れる。✎ の列のぶん、ほかの列のすき間を詰め、VM の Chromium で 360px の幅を確かめる。
8. **「自動×」の印**は、新しい順のヒントのセルに `<span class="sub">自動×</span>` を足す。**「難」の盤面**は、`boardRows` が、その盤面の記録に「難」が 1 回でもあるかを返し、盤面のセルの下の段に「難」と出す。
9. **ほかのタブとの合わせ**: `syncFromStore` で備考も読み直す。書く欄を開いているあいだにほかのタブから知らせが来たら、一覧は作り直さず（書きかけの文と、キーボードを消さないため）、閉じたときに作り直す。
10. **書き出し・読み込み**: `RecordsData` に `notes`（無くてもよい）を足す。`exportText` は、備考か印のある記録の行に `memo`、`hard`、`autoX` を、ある欄だけ足す。`parseExport` は、`memo` が文字列、`hard`・`autoX` が真偽値でなければ、ファイル全体を読まない。`importRecords` は、同じ鍵の項目を、文と「難」は今のスマホにあれば今のまま、無ければファイルの方、「自動×」はどちらかにあれば付ける、で合わせる。
11. **全部消す**: 記録、盤面の形と一緒に、備考も `{}` にする。
12. **確かめ用のページ**: `TRIAL_KEYS` に `notes`（`nekopatch-preview-notes-v1`）を足し、`trialStorage` が最初に写すキーにも入れる。
13. **キー操作**: 文字を打つ欄（`input` の `text` と `textarea`）の上では、文書全体のキー操作を受けない。欄で決定（Enter）を押したら、欄から外して（`blur`）キーボードを閉じ、保存する。
14. **見た目**: 本文は `user-select: none` なので、書く欄だけ `user-select: text` にする。「難」のボタンは `aria-pressed` で押された見た目を出す。CSP があるので、見た目は `style.css` に書く。

## Risks / Trade-offs

- [今の版のタブが残っていると、そのタブでのクリアに「自動×」が残らない] → 入れ替えの前に、ナンにねこパッチのタブを全部閉じてもらう（今までと同じ手順）。
- [✎ の列で、一覧が横にはみ出す] → 列のすき間を詰め、VM の Chromium で 360px の幅を確かめる。はみ出すなら、✎ を日時のセルの中に入れる。
- [書く欄を開いたまま、ほかのタブで記録が増えても、一覧が古いまま] → 閉じたときに作り直す。保存のときは必ず読み直すので、ほかのタブの分は消さない。
- [`maxlength` は、絵文字の一部を 2 文字に数えるので、絵文字が多いと 30 文字より少なくしか書けない] → ひと言の上限なので困らない。

## Migration Plan

- 新しいキーを足すだけで、今の値を移す処理は無い。
- 戻すときは、`gh-pages` を 1 つ前のコミットに戻す。戻した版は備考を知らないが、`nekopatch-notes-v1` には触らないので、もう一度入れ替えれば備考は戻る。戻した版のタブで遊びかけの盤面を保存し直すと、その問題の `autoXUsed` だけが消える。
