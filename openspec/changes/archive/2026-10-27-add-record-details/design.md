# Design

## Context

- 記録の一覧は `src/ui/web/app.ts` の `renderList` が作る。新しい順の行は `historyRows`、盤面ごとの行は `boardRows`（どちらも `src/core/records.ts`）。同じ盤面は、大きさ・難しさ・盤面の符号が同じ記録（`boardGroup`）。
- 備考は `notes`（`nekopatch-notes-v1`、判断 c995）、もらった盤面の印は `receivedBoards`（`nekopatch-received-v1`、判断 73b0）。どちらも記録の鍵 `at|n|d|t|h` で引く。
- ナンが書いた文は、表を作ったあとで `textContent` で入れる（`fillNotes`）。
- 共有（share-board）で、行の右に「遊ぶ」「送る」が縦に並び（`actsCell`）、どの行も 3 行分の高さになった。

## Goals / Non-Goals

- Goals: 年の見出し、盤面の欄を押したときの詳しい情報、行を 2 行に収めること、難しさの名前。
- Non-Goals: 保存の形の変更（新しいキーは足さない）、詳しい情報からの備考の書き直し、成績の表の幅。

## Decisions

### 詳しい情報の中身はロジックで作る

- `src/core/records.ts` に `boardPlays(records, boards, n, d, code)` を足す。その盤面の記録を日時の順に並べ、何回目か（`nth`）と前の回とのタイムの差（`diff`、1 回目は null）を付けて返す。新しい順の「2回目」や前回比と同じく、`classifyPlays` の順（保存の順 = 日時の順）で数える。
- 年月日・時刻の文字、備考、もらった盤面の文字は、画面の側（`app.ts`）で作る。送ってくれた人の文字は、共有と同じ `scoreLabel(sender)` を使う。
- 代わりの案: 画面の側で `records` を絞り込む。数え方が新しい順の行とずれるおそれがあり、UI 無しでテストできないので選ばない。

### 盤面の欄をボタンにする

- 盤面の形がある行の盤面の欄の中身を、`button.boardBtn`（`aria-expanded`、`data-open` に開く単位の鍵）にする。見た目は枠の無い文字で、盤面 ID の横に ▾（開いているときは ▴）を付ける。行そのものを押す形にはしない（「遊」「送」と混ざらないように。ナンが ✎ のときに避けた形）。
- 開いている単位は 1 つの変数 `detailKey` で持つ。新しい順は記録の鍵、盤面ごとの並びは `n|d|code`。別の盤面を押すと置き換わり、同じものを押すと null に戻る。並びと絞り込みを変えたら null にする。「もっと見る」、備考の書き直し、別のタブでの記録の追加では閉じない（開いていた行が一覧から無くなったら null にする）。
- 詳しい情報は、行のあと（備考の行と書く欄のあと）に `tr.detailRow` として足し、中に小さな表を置く。備考の文は、表を作ったあとで `textContent` で入れる（今の `fillNotes` と同じ）。

### 年の見出しの行

- 新しい順で、行の年（`new Date(at).getFullYear()`、スマホの時刻）が前の行と違えば、その前に `tr.yearRow`（`th colspan`）を足す。一番上の行の前にも必ず足す。`historyRows` の `limit` は記録の行だけを数えるので、見出しの行は 30 行の数に入らない。

### 行を 2 行に収める

- `actsCell` のボタンを「遊」「送」の 1 文字にし、横に並べる。読み上げとテストのため、`aria-label` に「遊ぶ」「送る」を入れる。
- 遊んでいる途中に「遊」を押したときは、今までボタンの文字を「もう一度押す」に変えていた。1 文字のボタンが広がると表が揺れるので、文字は「遊」のまま、押された見た目（色）と `aria-label`「もう一度押す」にする。知らせの文（「もう一度押すと、…」）は今までどおり出す。
- 盤面ごとの並びは、「初回」の列をやめ、「ベスト」の欄の下の段（`.sub`）に初回を出す。見出しも「ベスト」の下に小さく「初回」。
- 残りは、セルの左右のすき間を 4px から 2px にし、列の幅を決めている見出し（「タイム」「ヒント」）の文字を小さく（0.74rem）し、「遊」「送」の内側のすき間とあいだを 1px ずつ詰めて、幅 384px で収める（360px でも、表ははみ出さなくなった）。happy-dom は配置を計算しないので、幅は自動テストで確かめられない。VM の Chromium（CDP）で 384px と 360px の写しを撮り、表の `scrollWidth` と行の高さを測って確かめる。

### 難しさの名前

- `LEVEL_NAMES`（`src/core/play.ts`）を「簡単」「普通」「難しい」にする。成績の表、絞り込み、一覧、クリアの画面、案内、送る文は、どれもここから名前を取っている。
- 難しさを選ぶ所（`index.html` の `diffSel`）には名前が直接書いてあり、2 か所になっている。起動のときに `LEVEL_NAMES` から選択肢の文字を入れ直し、名前の出所を 1 つにする。HTML の文字も同じ名前に直す（スクリプトが動くまでの一瞬の表示のため）。
- 仕様の文の「かんたん」「ふつう」「むずかしい」は、難しさの段階を指す言葉として残す（アーカイブ済みの多くのシナリオを書き換えずに済む）。`record-details` の要件に、その読み方を書く。

## Risks / Trade-offs

- 幅 384px 以上では、備考も「自動×」も無い行は 2 行に収まる。360px では、「2回目」と 🎁 の両方が付いた行だけが 3 行になる（2026-10-27、VM の Chromium で測った）。ナンのスマホで右端がはみ出すなら、行には「遊ぶ」だけを残し、「送る」は詳しい情報の中に移す（ナンの答え）。
- 「遊」「送」のボタンは、幅 27px ほどで、あいだが 3px と近い。押し間違えても困らない作りにしてある（上の「くろが決めた細かいところ」）。
- 送る文の難しさの名前が「普通」などに変わる。リンクの中身は数（`d`）なので、前に送ったリンクも今までどおり開ける。
- 記録がとても多いとき、詳しい情報を開くたびに全部の記録を 1 回見る。開くときだけなので、困らない（成績の表も毎回全部を見ている）。

## Migration Plan

- 保存の形は変えないので、移す処理は無い。今の版のタブが残っていても、記録・備考・もらった盤面の印は消えない。
- 戻すときは、`gh-pages` を 1 つ前のコミットに戻して送る。
