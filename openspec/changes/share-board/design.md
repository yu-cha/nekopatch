# Design

## Context

- 盤面の形は、記録の鍵ごとに `nekopatch-boards-v1` に符号で残っている（490d）。符号から、答えがちょうど 1 つの問題を作り直せる（`restorePuzzle`）。盤面 ID は、符号から求める 5 文字の名前で、そこからは作り直せない。
- 記録の備考と「自動×」の印は `nekopatch-notes-v1` にある（c995）。今配信している版は、備考のキーの知らない欄を、保存し直すときに落とす。
- 同じ盤面をもう一度遊ぶ処理（`replay`）は、大きさ・難しさの選択を盤面に合わせ、状態を作り直して始める。もう一度遊んだ記録かどうかは、記録の並びから求める（`classifyPlays`）。
- ページは CSP で通信を禁止し、GitHub Pages で誰でも開ける。ナンも受け取る人も、Android の Chrome で遊ぶ。LINE は、トークのリンクを LINE の中のブラウザで開く。
- 画面の機能（保存、Worker、ファイルの書き出し、確かめの窓）は `AppEnv` を通して使い、テストでは偽物に差し替える。

## Goals / Non-Goals

**Goals:**

- 相手は、LINE のリンクをタップするだけで、同じ盤面を遊べる。記録は相手の Chrome に残る。
- リンクの中身（盤面とタイム）は、サーバーに届かず、ページの中だけで読む。ページの決まり（CSP）は変えない。
- 送る文に入るものが決まっていて、日時や備考が入らない。
- もらった盤面の印は、今の版のタブや戻した版が残っていても消えない。

**Non-Goals:**

- 盤面の文字を貼る欄、iPhone での確かめ。
- 送った相手や日時を残すこと、友だちのタイムを並べること。

## Decisions

1. **リンクの形**（判断 73b0）: `<ページのアドレス>?openExternalBrowser=1#n=<大きさ>&d=<難しさ>&b=<盤面の符号>&t=<秒>&h=<ヒントの回数>`。`t` と `h` は、両方あるか、両方無い。ロジックは `src/core/share.ts` に置く。
   - `shareFragment(盤面)` が `#` の後ろを作り、`shareText(ページのアドレス, 盤面)` が送る文（3 行）を作る。タイムは秒に切り捨てる（`formatTime` と同じ）。
   - `parseShareFragment(文字)` は、`&` と `=` で分け（ロジックは DOM の型を使えないので `URLSearchParams` は使わない）、`n` と `d` が選べる値、`b` が `restorePuzzle` で問題になる、`t`（0〜359999）と `h`（0〜9999）が 10 進の整数で両方あるか両方無い、を確かめる。1 つでも外れたら `null`。同じ名前の欄が 2 つあるときも `null`。知らない名前の欄は無視する。
2. **送る**: `AppEnv.share(文)` が、スマホの共有の画面（`navigator.share({ text })`）に渡し、結果（`shared`、`cancelled`、`copied`、`failed`）を返す。共有の画面が無いか、`AbortError` 以外で失敗したら、`navigator.clipboard.writeText` で写す。本物は `src/ui/web/share.ts` の `shareOrCopy(navigator の一部, 文)`（偽の navigator でテストする）。
   - 結果の知らせは、押した場所の近くに出す。クリアの画面は `#winShareMsg`、記録の一覧は `#recPlayMsg`、盤面の下のボタンは盤面の下の文の欄（`say`）。`copied` は「写しました。LINE などに貼ってください。」、`failed` は「送れませんでした。くろに相談してください。」。`shared` と `cancelled` は何も出さない（前の知らせは消す）。
   - 文に入れる値は、盤面 ID、大きさ・難しさ、タイムとヒントの回数、リンクだけ。数と base64url の文字だけなので、HTML としては扱わずに `text` で渡す。
3. **送る場所と付けるタイム**:
   - クリアの画面 `#winShare`「この盤面を送る」: いまクリアした記録のタイムとヒントの回数。
   - 盤面の下のボタンの並び `#shareBtn`「送る」: クリアしていなければタイム無し（2 行目は「これ解ける？」）。クリアしたあとなら、クリアの画面と同じ。
   - 記録の一覧: 「遊ぶ」と同じセルに、`<button class="send" data-n data-d data-b data-t data-h>送る</button>` を、「遊ぶ」の下に置く（横に並べると、360px の幅からはみ出すため）。新しい順はその記録の `t`・`h`、盤面ごとの並びは初回の記録の `t`・`h`（`boardRows` に初回のヒントの回数 `firstHints` を足す）。盤面の形の無い行には出さない。
4. **リンクを読む**: `AppEnv.takeLink()` が、アドレスの `#` の後ろ（`#` を除く）を返し、アドレスに `?` か `#` の後ろがあれば `history.replaceState` で消す。`AppEnv.onLinkChange` が `hashchange` を知らせる。起動の終わり（遊びかけの盤面を出すか、新しい問題を頼んだあと）と、`hashchange` のときに読む。空なら何もしない。
5. **案内** `#shared`（`#win` と同じく盤面の上に重ねる。`#win` より後ろに置いて、上に出す）:
   - 読めたとき: 「送られてきた盤面」、「8×8・ふつう　<盤面 ID>」、タイムがあれば「送ってくれた人: 3:25・ヒント 0 回」、遊びかけ（クリアしていない盤面に猫か × がある。`replay` の「遊ぶ」と同じ決まり）なら「遊ぶと、今の遊びかけの盤面はやめになります。」、ボタン「やめる」「この盤面を遊ぶ」。
   - 読めないとき: 「送られてきた盤面」、「このリンクの盤面は開けませんでした。」、ボタン「閉じる」。
   - 出しているあいだは時間を止める（`startTimer` は案内が出ていれば進めない）。閉じたら、クリアしていない盤面があれば時間を進める。
   - 「この盤面を遊ぶ」: 案内を閉じ、`replay(問題, 難しさ)` で始め、もらった盤面の印（送った人のタイムとヒントの回数。無ければ無し）を、いま遊んでいる問題の状態 `received` に持つ。
6. **もらった盤面の状態**: `received`（`{ sender: { time, hints } | null } | null`）。`setPuzzle` で状態を作り直すとき（新しい問題、「もう一度この盤面」、記録の一覧の「遊ぶ」）に `null` に戻す。遊びかけの保存（`nekopatch-v1`）には、`null` でなければ欄 `received: {"senderTime": 205000, "senderHints": 0}`（タイム無しは `{}`）を書く。読むときに形が違えば、欄が無いものとして読む（`hints` が読めないときと同じく、読めない保存データとしては扱わない）。
7. **クリアしたとき**: `received` が `null` でなければ、記録の鍵で `nekopatch-received-v1` に保存する（盤面の形 → 備考と印 → もらった盤面の印 → 記録の順。どれかに失敗しても、余るのは記録の無い鍵だけ）。送った人のタイムがあれば、クリアの画面 `#winVersus` に、秒の単位の差（`Math.floor(今回 / 1000) − Math.floor(送った人 / 1000)`）で「送ってくれた人（3:25）より 0:30 速い！」「…より 0:35 遅い」「送ってくれた人（3:25）と同じタイム！」を出す。
8. **もらった盤面の印の保存**（判断 73b0）: `{"<記録の鍵>": {"senderTime": <ミリ秒>, "senderHints": <回数>}}`、タイム無しは `{}`。`parseStoredReceived` は、鍵が記録の鍵の形で、値がオブジェクトで、`senderTime` と `senderHints` が 0 以上の整数で両方あるか両方無いものだけを使う。外れたら `intact: false` を返し、`SaveStore` が元の文字を `<キー>-unreadable-<日時>` に残してから、読めた分で書き直す（490d と同じ）。
9. **記録の一覧**: 新しい順で、もらった盤面の記録の行の次に `<tr class="noteRow received">` を足し、「もらった盤面（送ってくれた人 3:25・ヒント 0 回）」（タイム無しは「もらった盤面」）と出す。文は数から作るが、備考と同じく、表を作ったあとで `textContent` で入れる。備考の行や書く欄は、その下に出す。
10. **ほかのタブとの合わせ**: `syncFromStore` で、もらった盤面の印も読み直す。クリアしたときは、読み直してから足す。
11. **書き出し・読み込み**: `RecordsData` に `received`（無くてもよい）を足す。`exportText` は、もらった盤面の記録の行に `received` を足す。`parseExport` は、`received` があって読めなければ、ファイル全体を読まない。`importRecords` は、同じ鍵の印が今のスマホにあれば今のまま、無ければファイルの方を使う。
12. **全部消す**: 記録、盤面の形、備考と一緒に、もらった盤面の印も `{}` にする。
13. **確かめ用のページ**: `TRIAL_KEYS` に `received`（`nekopatch-preview-received-v1`）を足し、`trialStorage` が最初に写すキーにも入れる。リンクのページのアドレスは、開いているページの `origin + pathname` なので、確かめ用のページから送ると `…/nekopatch/preview/` のリンクになる。
14. **見た目**: `#shared` のカードは `#win` と同じ見た目にする。クリアの画面のボタンは 3 つになるので、「この盤面を送る」を上の行に、「もう一度この盤面」「次の問題」を下の行に置く。VM の Chromium で 360px の幅を確かめる。

## Risks / Trade-offs

- [LINE が、外のブラウザで開くときに `#` の後ろを落とす] → LINE の説明に書かれていないので、確かめ用のページで、ナンのスマホの LINE（Keep メモ）から開いて確かめる。落ちるなら、判断 73b0 を見直す。
- [Android の Chrome の共有の画面に LINE が出ない（LINE が入っていない、など）] → 共有の画面の「コピー」か、写した文を LINE に貼ってもらう。
- [記録の一覧の「送る」で、行の高さが増える] → 「遊ぶ」「送る」を小さいボタンにして縦に並べる。新しい順のセルはもともと 2 段なので、高さはあまり変わらない。
- [案内を出したまま、盤面の下のボタン（ヒントなど）を押せる] → 盤面の操作は、案内が盤面を覆うのでできない。ほかのボタンは今までどおり動く（案内はそのまま）。困る操作は無い。

## Migration Plan

- 新しいキーを足すだけで、今の値を移す処理は無い。
- 戻すときは、`gh-pages` を 1 つ前のコミットに戻す。戻した版は `nekopatch-received-v1` に触らないので、もう一度入れ替えれば「もらった盤面」の印は戻る。戻した版でリンクを開くと、いつものゲームが出る。
